# 通用逆向方法论 —— 把任何网页版 AI 接入本仓库

本仓库内置了 DeepSeek / 千问 / 豆包 / MiMo 四个通道。如果你常用的 AI 在别的平台
（Gemini、Grok、Kimi、Poe、你自建的任何网页对话……），**不需要等我们适配**：
按照本文的五步方法论，你自己（或你手头的任意 AI 助手）就能把它接入进来。

整个过程不需要编程基础——第 1~4 步只是"复制粘贴 + 观察"，第 5 步可以把本文
末尾的【AI 协作提示词】直接丢给 Gemini / Grok / Claude，让它替你改代码。

---

## 第 0 步：拿到你的 Cookie（新手必读，2 分钟）

后面所有步骤都要用到"完整 Cookie"——它就是你登录态的本体。获取方法：

1. 浏览器登录目标网页版（保持登录状态）
2. 按 `F12` 打开开发者工具 → **Network**（网络）标签
3. 在网页上**随便发一条消息**（不发就没有请求可看）
4. Network 列表里点开**任意一条**发往该网站的请求 → **Headers**（标头）→
   往下滚到 **Request Headers**（请求标头）区域
5. 找到 **`Cookie:`** 这一行 → 右键它的值 → **Copy value**（复制值）

三个新手常见疑问：

- **"我只看到部分 cookie 怎么办？"** → 你可能看的是 Application → Cookies 面板
  里被筛过的视图。以 Network 面板请求头里的 `Cookie:` 整行为准，**整行复制，
  一个都不要删**。
- **"为什么有些 cookie 我复制不到？"** → 最关键的凭证（如 `sessionid`、
  `serviceToken`）被浏览器标记为 httpOnly，网页脚本读不到，但 DevTools 的
  Network 面板能完整看到——所以必须从这里复制。
- **"Cookie 会失效吗？"** → 会。退出登录、平台风控、自然过期都会让它失效。
  失效后重新登录再复制一次即可（各服务的 `/admin/cookie` 可以不重启热更新）。

> ⚠️ Cookie 等于你的账号登录态，等同密码：不要发到公开场合，
> 只填进自己电脑上的 config.json 或发给你信任的配置工具。

## 第 1 步：抓包（找到真正的聊天接口）

1. 浏览器登录目标网页版，按 `F12` 打开开发者工具 → **Network**（网络）标签
2. 在网页上发一条消息
3. Network 列表里刷出的请求中，找到**携带你那条消息、且响应是流式文本**的那一条
   - 快捷方法：筛选框输入 `chat` / `completion` / `message` 逐个试
   - 点开请求 → **Payload/载荷** 里应该能看到你刚发的文字
4. 右键该请求 → Copy → **Copy link address**（完整 URL）

## 第 2 步：鉴权分析（判断难度，30 秒）

在 Headers → Request Headers 里看有什么：

| 你看到的东西 | 难度 | 说明 |
|--------------|------|------|
| 只有 Cookie | ⭐ 简单 | 登录态即凭证，参照 doubao2api |
| Cookie + `Authorization: Bearer xxx` | ⭐ 简单 | token 可能在 Cookie 或 localStorage 里 |
| `x-sign` / `x-bogus` / `_signature` 等签名头 | ⭐⭐⭐ 困难 | 需要逆向签名算法，建议换平台或用浏览器桥接方案 |

**关键验证**：该请求是否能在"没有浏览器指纹"的情况下重放成功——这就是第 3 步。

## 第 3 步：重放验证（成败的分水岭）

把请求用 curl 在浏览器外面发一遍：

```bash
curl -s -X POST "第1步复制的完整URL" \
  -H "Content-Type: application/json" \
  -H "Cookie: 你从F12里复制的完整Cookie" \
  -H "其他必要的头..." \
  --data-binary @请求体.json
```

- **返回 200 + 流式内容** → ✅ 可以接入，继续第 4 步
- **返回 401/403** → Cookie 不全（注意 httpOnly 的要复制完整）或需要签名头 → 难度升级
- **返回 4xx 且带验证/滑块提示** → 风控较严，谨慎行事

## 第 4 步：响应格式分析

上游响应通常是 SSE（`text/event-stream`）。把流存成文件，找出三样东西：

1. **正文增量在哪个字段**（豆包是 `CHUNK_DELTA` 的 `text`，千问是 `multi_load/iframe` 的累积 `content`）
2. **结束标记是什么**（豆包 `SSE_REPLY_END`，千问最后一条快照）
3. **增量还是累积**（决定要不要做前缀差值）

## 第 5 步：套模板（让 AI 替你写代码）

复制 `services/doubao2api/` 整个目录作为起点（它是本仓库最干净的参考实现），
只需要改 **4 个函数**，其余协议层全部复用：

| 要改的函数 | 改什么 |
|-----------|--------|
| `build_query` / 上游 URL 常量 | 换成第 1 步的接口地址 |
| `build_doubao_body` | 换成第 1 步的请求体结构 |
| `doubao_chat` | 换成第 4 步的解析逻辑（产出 delta 和 done） |
| `config.json` | 填入你的 Cookie 和自定的 api_key |

改完 `python services/你的服务/xxx.py --check` 自检，通过即接入完成。

## 风险与边界（务必阅读）

- 同样违反目标平台服务条款，**小号原则不变**
- 需要签名逆向的平台（第 2 步看到签名头）性价比极低，不建议
- Cookie 会过期，失效表现与更新方式同其他服务
- 欢迎给本仓库提 PR：适配了新平台就按上面的目录结构提交
